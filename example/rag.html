01 · The Idea

What is RAG?

Models don't know your documents. RAG fixes that: look them up first, then answer using them.

04 · Worked Example

One real case.

User asks
"Can I work from Portugal for the summer?"
1
Embed
Turn the question into a vector like [0.21, -0.84, 0.12, ...]. The numbers let the computer measure similarity.
2
Search
Compare the vector to every chunk in the corpus. Pull the 3 most similar: 📄 HR Handbook §6.1 — "Remote Work International"
📄 HR Handbook §4.2 — "Leave & Time Off"
📄 HR Handbook §6.3 — "Tax Implications Abroad"
3
Build the prompt
Stick the chunks into the prompt, before the question. The model now has everything it needs.
4
Generate
The model reads the chunks and writes an answer. With the policy text right there, it can quote it and cite the section.
→ Answer returned to user
"Yes — you can work internationally for up to 30 days per year with manager approval. Portugal for the full summer exceeds the limit, so you'd need a special arrangement. (per §6.1)"
05 · Code Sketch

The shape in code.

Tap a line to see what it does.
# 1. find the most relevant documents
docs = retrieve(query, top_k=3)
 
# 2. build a prompt that includes them
prompt = f"Answer using:\n{docs}\n\nQ: {query}"
 
# 3. ask the model, return answer + sources
answer = model(prompt)
return answer, docs
