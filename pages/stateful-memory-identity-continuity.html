Recognizing you across sessions

A way to know that the person opening a chat today is the same person who opened one last week, so the right memory gets loaded.

01What it is

A stable key tied to you, not to a chat.

The system tags every memory with a user key (a login, an account ID, a device token). When a new chat starts, the system reads the key, finds the memory drawer that belongs to it, and loads from there. Without this, every session would meet a stranger.

02An example

Same key, two different days.

User opens a new chat a week apart
Mon, 14 Apr
user_id: nareman_42
"Hi Nareman. Last time you were planning a Rome trip. Anything new on that?"
same key → same drawer
Identity link
Mon, 21 Apr
user_id: nareman_42
"Welcome back. Hotels near Termini for 22 May, like we discussed?"
Same key, week apart. The chat is new but the memory drawer is the same. The reply picks up where the last one left off.
03Where it fits

How it sits next to nearby ideas.

Sits next to
The memory store itself. The store holds the notes. Identity is the label on the drawer so the right drawer opens for the right person.
What can go wrong
If two people share a login, their notes mix. If the key is weak (just a cookie), a logged-out visitor loses everything. Strong identity = strong memory.
04When it matters

When to reach for it.

  • The product is one assistant used by many people, and each one should only ever see their own memory.
  • Sessions are short and frequent: people open the app, ask a quick thing, close it, come back hours later.
  • You need the system to honour "this is me again" without the user retyping context every time.
