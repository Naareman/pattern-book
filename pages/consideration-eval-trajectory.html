Agent trajectory evaluation

Grade the whole path the agent took to reach an answer, not only the final reply. The right answer reached via the wrong steps is still a problem worth catching.

01What It Is

Score the path, not only the destination.

Trajectory evaluation scores the full sequence of steps an agent took to reach its answer, not just the answer itself, so an agent that lucked into the right result via wasteful steps is rated lower than one that took the direct path.

02An Example

Grading a flight-booking run.

Task: book a flight from Cairo to Dubai next Friday run #4172
01
search_flights(origin="CAI", dest="DXB", date="2026-06-05")
Right tool, correct city codes, correct date.
Good step
02
search_hotels(city="DXB")
User asked for a flight only. The hotel call is off-task and wastes a tool budget.
Off-task
03
select_flight(id="EK924")
Picked the cheapest direct option matching the user's earlier preference for mornings.
Good step
04
confirm_booking() → success
Final answer is correct, but the run earns a deduction for step 2.
Goal reached
Final-only grading would mark this a pass. Trajectory grading shows a clear inefficiency to fix.
03Where It Fits

How it relates to nearby ideas.

What it is
A grading shape designed for agents that take many steps. It looks at the trace of actions, not only the final output.
Pairs with
Trace logs from the running system feed the grader. Without a recorded trace, there is nothing to score.
04When It Matters

When to reach for it.

  • Agents that use tools, browse, or run code: where the path matters as much as the answer.
  • You suspect the system is reaching answers by luck and want to catch that before it bites in production.
  • You need to spot waste: extra tool calls, dead-end loops, or recovering from a mistake the system should not have made.
