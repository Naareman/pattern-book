Mixed-modality handoff

When a chat starts in voice and then a user sends a photo, or starts in text and pivots to audio, the system has to swap input handlers while keeping the thread of the conversation intact.

01What Is It?

Pass the baton, keep the memory.

A mixed-modality handoff routes each new input type to the right handler and rewrites earlier turns into a form the next model can read, so the conversation thread survives a switch from voice to image to text.

02An Example

Voice, then a photo, then text.

audio in
User (voice): My oven is making a weird sound. Should I worry?
handler
System: transcribes audio → saves the text turn.
image in
User (photo): a picture of the back of the oven.
handler
System: sends the image plus the earlier text turn to a vision model → saves a short description of the photo.
text in
User (text): Is that the fan?
handler
System: plain text model sees the full thread (voice transcript + photo description + this question) and answers.
The work: route each new input to the right handler, and keep one shared thread of history so the next call always has the full picture.
03Where It Fits

How it sits next to nearby choices.

Builds on
Picking how to handle each input on its own is the foundation. Handoff is what happens when several of those inputs arrive in sequence.
Lives in the UI
The actual mid-chat switch (mic icon to camera icon, etc.) is a user-surface job. This page is about the routing and shared thread behind that switch.
04When It Matters

When to think about it.

  • The product invites users to switch input shapes inside one session (voice plus camera, text plus screenshot).
  • Earlier turns carry context the later answer needs ("the sound I just described" or "the photo I just sent").
  • Different handlers live behind different vendors or models, and the thread needs to flow across them.
