Structure the steps

How to decide what order and shape your system's calls take.

Simple flows

Want to answer in a single round trip to the model? → Single-call patterns↗
Want steps to run one after another in a fixed order? → Sequential pipelines↗
Want multiple sub-tasks to run at the same time and merge their results? → Parallel / fan-out↗

Loops and branches

Want the model to think, act, see the result, and loop until it has enough? → Iterative loops (ReAct, reflection)↗
Want an entry point that reads the request and sends it to the right specialist? → Router / dispatcher↗
Want a planner to break the goal into steps and hand each to an executor? → Hierarchical planning↗
Want the path through your system to change based on what the model finds at runtime? → Conditional branching↗
