Real-time / Streaming

The disciplines for building systems where the gap before the first word matters far more than total generation time.

Conditional Scope
Applies to: only systems with sub-second, word-by-word output (streaming chat, voice, live transcription). Systems that wait for the full answer can skip it.
Here, the wait before the first word, and a steady flow of output, matter more than the total time.
01The Idea

What does real-time mean?

A token (a token is a small piece the AI works in: roughly a word, or a slice of an image or sound) is the basic unit of generation. When you send a prompt (the text you send the AI), it generates every token before sending a response. The wait from "I sent the message" to "I saw the first word" is called TTFT (time to first word). It is the number that determines whether an AI feels instant or sluggish.

One technique changes everything: streaming, which sends each token as it is generated instead of waiting for the full answer. The total time is the same. The felt wait drops to almost nothing. This page is a discipline for reasoning about all the decisions that change once you commit to streaming output.

03What This Covers

The disciplines inside Real-time / Streaming.

This is a discipline, not a mechanism. The part that makes words appear progressively on screen lives in the User Surface layer. This page owns the thinking frameworks that apply once you commit to streaming.

Streaming the output

Streaming Output Discipline Decide when streaming is worth the effort and when waiting for the full answer is fine.
Time-to-First-Word Frameworks Measure the wait before the first word, and set a target for each product (voice is tighter than chat).
Continuous Context for Voice Handle taking turns and interruptions, so the conversation stays coherent when the user cuts in.

Doing it safely and cheaply

Streaming Eval Check answer quality as it streams, not only once the full response is done.
Streaming Safety Catch harmful content in a partial answer, and stop the stream cleanly when needed.
Streaming Validation Check structured output as it arrives, since a half-finished answer can look broken mid-stream.
Backpressure and Cancellation Pause or stop a stream when the user leaves or cannot keep up, instead of wasting work.
Streaming Cost Attribution Charge fairly for a stream that was cut short, since partial answers still cost real work.
All of these are disciplines for reasoning and deciding. The parts they rely on each have a home in the layers.
04A Real Example

Where every millisecond counts.

Voice Assistants
People expect a spoken reply to start within about 500ms. A two-second pause breaks the illusion of conversation entirely. Streaming audio lets the AI speak the first sentence while still generating the rest. Barge-in handling (the user speaking while the AI is mid-sentence) must interrupt generation cleanly.
TTFT Critical
AI Code Editors (Autocomplete)
Suggestions that arrive in under 100ms feel like the editor is reading your mind. Suggestions that arrive after a second feel like an interruption. Speed here is the product. Streaming validation is critical because partial code suggestions must still parse.
Sub-100ms Target
Live Transcription
Captions must appear within one word of the speaker. Latency above 2-3 seconds makes them useless for deaf viewers. Backpressure handling matters here: if the network drops, the system needs to catch up without losing words or doubling them.

05Tradeoffs

The price you pay.

LowHigh
Infrastructure cost
Complexity added
Safety difficulty
Answer quality
Faster hardware and more replicas cost real money. Streaming requires clients to handle partial responses, cancellation signals, and mid-stream errors. Safety filters that rely on reading the complete response must be redesigned. The one thing streaming does not cost: answer quality. The model generates the same tokens either way. Speed and correctness are separate knobs.
