Schema Enforcement

Require the model to fill specific named fields, not just produce text that looks structured.

01What It Is

Fields, types, required.

Schema enforcement means passing a formal field specification alongside the prompt so the model must populate every declared key with a value of the correct type. Modern APIs accept a JSON Schema object in the request; the model's output is then validated against it before being returned. This goes beyond asking the model to "reply in JSON" in the prompt: the schema is machine-readable, the validation is automatic, and missing or wrongly typed fields are caught before your code ever sees the response.

02An Example

Required fields, enforced.

Without schema
// Prompt said "reply in JSON"
// Model decided its own shape:
{
  "result": "positive",
  "explanation": "The review..."
  // missing: score, language
  // score is a string, not number
}
With schema
// Schema declared required fields:
{
  "sentiment": "positive",
  "score":     0.87,
  "language": "en"
  // all fields present, types match
}
03Where It Fits

Its place in the taxonomy.

L4
Home layer
Output Shape & Decoding sub-axis. The schema is passed at call time and shapes the model's output inside that single call. No second call, no separate validator model.
L4
Neighbor
Constrained Decoding enforces structure at the token-probability level. Schema Enforcement works at the field-and-type level and typically sits above the decoding layer, often implemented by the serving infrastructure wrapping a constrained decoder.
L2
Cross-reference
If a separate validator model scores or corrects the output, that moves to L2 Verify. Schema Enforcement is the single-call, single-model version.
Filing rule: Shaping happens inside one call, declared at call time. L4 Output Shape & Decoding.
04When It Matters

Who needs this.

Any pipeline that passes model output directly to downstream code. Without a schema, the model occasionally invents field names, omits required keys, or returns a number as a string. Each of these breaks a JSON parser or a typed data model. Schema enforcement shifts that class of failure from a runtime exception to a guaranteed-valid response.
