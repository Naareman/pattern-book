Pull from a live source

For facts that change by the hour, search a live source at question time instead of a pile of stored documents. Read-only: the system asks, reads, and uses the answer.

01What is it?

A read-only call to a fresh source.

Some facts move too fast to store: today's news, current stock prices, this morning's flight status. Instead of indexing them ahead of time, the system runs a live lookup at the moment the question arrives. The look-up may be a web search, a weather feed, or a database query. It only reads; it never changes anything in the source. The result is treated like any other retrieved piece and fed to the model.

02An example

Three questions, three live calls.

→
Read-only live call Weather feed Calls a public weather feed for "Cairo, EG" and reads back the current conditions.
Why live: the weather changes every hour. A stored snapshot would be stale before the user even reads the answer.
03Where it fits

Where it fits.

Sits next to
Search over a prepared library. A live look-up plays the same role: it pulls in passages the model would not know from training. The difference is the source is queried fresh each time.
Read-only by rule
A live look-up only reads. The moment the system writes, books, posts, or cancels something, it has crossed into an action, which is a different shape entirely.
Watch for
Latency and outages. A live call can add hundreds of milliseconds and can fail. Plan a fallback: a cached value, a graceful "I could not check just now", or a stored backup.
04When it matters

When to reach for it.

  • The answer depends on facts that change daily or by the minute.
  • A trusted live source already exists (an API, a search engine, a weather feed) and is cheap to call.
  • Storing a snapshot would mean serving stale answers most of the time.
