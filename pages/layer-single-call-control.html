Layer · L4

Single-Call Control

Every knob you can turn inside one message to the AI, before and after it thinks.

A prompt (the text you send the AI) is not just instructions. It sets a role, supplies examples, guides reasoning, and shapes the reply, all before a single token (a token is a small piece the AI works in: roughly a word, or a slice of an image or sound) leaves the model. L4 covers every technique that operates inside that single boundary.

Nothing here needs a second call. The moment you add a second call, or a second model, you have crossed into L5 or L2.

What Do You Want to Do?

What you want Use this
Get it to copy a style I show → Few-Shot ↗ Give it a few examples to copy. Get an answer by just asking → Zero-Shot ↗ Describe what you want, no examples. Get a hard problem right → Chain-of-Thought ↗ Ask it to think step by step. Get a more reliable answer → Self-Consistency ↗ Sample multiple reasoning paths, take the most common. Get the answer in a fixed format → Structured Output ↗ Tell it the exact shape to return. Get it to fix its own mistakes → Self-Reflection ↗ Ask it to review and revise its answer inside the same call.
Inside This Layer
Axis: what you shape, and at which point, inside one model call.
Input Shape
Zero-Shot Framing ↗
Asking the AI directly with no examples, relying on its trained knowledge alone.
Few-Shot Framing ↗
Supplying a handful of input/output examples ("shots") inside the prompt so the AI picks up the pattern before answering.
Role / Persona
Giving the AI an identity ("You are a careful lawyer") to bias its tone, vocabulary, and caution level.
Delimiters
Using explicit markers (XML tags, triple backticks, horizontal rules) to separate system instructions, user input, and data so the AI does not mix them up.
Negative Prompting
Telling the AI what NOT to do, say, or include, narrowing the answer space by exclusion.
Meta-Prompting
Asking the AI to write or improve the prompt itself, using its own generation to bootstrap better instructions.
Prompt Templates
Reusable prompt skeletons with placeholders that get filled at runtime, keeping structure consistent across many calls.
Example Selection
Choosing which few-shot examples to include based on similarity or difficulty relative to the current query, rather than always using the same fixed set.
Example Ordering
Arranging examples in a deliberate sequence (e.g. hardest last, or most similar to the query last) because position affects what the AI attends to.
Context Packing
Fitting as much relevant information as possible into the prompt's token budget without exceeding the model's context window.
Lost-in-the-Middle Mitigation
Placing the most important content at the start or end of a long prompt, because models reliably attend to edges more than the middle.
Prompt Compression
Shrinking the prompt (via summarization, selective deletion, or learned soft tokens) to reduce cost and latency without losing the meaning the model needs.
Cognitive Strategy
In-Prompt (authored as text the model follows)
Step-Back
Asking the AI to first answer a broader, simpler version of the question before tackling the specific one, surfacing relevant principles it might otherwise skip.
Least-to-Most
Instructing the AI to decompose a complex problem into simpler sub-problems and solve them in order from easiest to hardest, within one call.
Plan-and-Solve
Prompting the AI to write an explicit plan first and then execute each step, reducing arithmetic and logical errors on multi-step tasks.
Analogical Prompting
Prompting the AI to generate or recall a relevant analogy before answering, using structural similarity to transfer reasoning from a known domain.
Chain-of-Thought ↗
Asking the AI to show its reasoning steps before giving a final answer, improving accuracy on multi-step problems by externalizing intermediate work.
In-Decoding (search over generations)
Tree-of-Thoughts
Generating multiple partial reasoning paths in parallel and pruning or expanding them like a search tree, all within one call, to find better solutions than a single linear chain.
Skeleton-of-Thought
First generating a bare outline (the skeleton), then filling in each section in parallel within the same call, reducing latency on long structured outputs.
Self-Consistency as Search ↗
Sampling N independent reasoning paths from the same model and same prompt, then taking a majority vote over final answers. Filing note: this is L4 when same model and same prompt; if different models or prompts are used, it becomes L2 Combine (Ensembling).
Self-Verification
Self-Reflection ↗
Asking the AI to critique and revise its own answer within the same call, catching obvious errors before the reply reaches the user.
Chain-of-Verification
Prompting the AI to generate explicit yes/no verification questions about its own answer and then answer each one, surfacing specific factual claims that may be wrong.
Self-Ask
Prompting the AI to identify and answer its own follow-up sub-questions before giving a final answer, decomposing complex queries into checkable steps.
Single-Model Debate-Then-Decide
Having the AI argue both sides of a question within one call and then render a verdict, using the internal tension to surface blind spots. Filing note: if a second call or a second model is involved, this moves to L2 Verify.
Output Shape & Decoding
Structured Output ↗
Instructing the model to return data in a defined format (JSON, Markdown table, XML) so downstream code can parse it reliably.
Schema Enforcement
Providing a formal schema (JSON Schema, TypeScript interface) inside the prompt or via API settings so the model knows exactly which fields are required and what types they must be.
Constrained Decoding
Restricting the model's token-by-token generation at the API or runtime level so it can only produce outputs that conform to a grammar or allowlist.
Streaming with Validation
Validating partial output as tokens (the model's smallest output units) stream in, so errors are caught early rather than after the full reply arrives. The streaming discipline is C7; this is the L4 mechanism.
Format Coercion
Rephrasing or post-processing the model's raw output to match a required format when the model did not follow instructions precisely.
Temperature and Sampling
Setting the randomness of token selection: low temperature makes answers more deterministic and focused; high temperature makes them more varied and creative.
Logit Biasing
Adjusting the raw probability scores ("logits") for specific tokens before sampling, to boost or suppress particular words or characters in the output.
Stop Sequences
Specifying character strings that cause generation to halt immediately when encountered, giving precise control over where the output ends.
Beam Search
Keeping multiple candidate token sequences in parallel during generation and selecting the highest-probability complete sequence, trading speed for output quality.
Filing rule: if it happens inside one call to one model, it belongs here. A second call is L5. A second model is L2.
