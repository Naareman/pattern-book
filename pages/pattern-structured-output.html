Pattern

Structured Output

Tell the model the exact shape to return, so the answer is predictable and a program can read it directly.

01The Idea

What is it?

Structured output is telling the AI the exact shape to return, like a list of named fields, so your code can read the answer without guessing.

02See It Work

Free text vs. fixed shape.

Same request, two responses. Watch the fields populate on the right.

Request "Extract the vendor name, invoice date, and total amount from this invoice."
Free text
Structured output
{   "vendor": ,   "date": ,   "amount": ,   "currency":
}

03When It Matters

Use it, or skip it?

Structured output shines when the answer feeds a system, not a person. It comes with one real constraint: the model must follow the schema exactly, and you should validate what comes back.

✓
Feeding another system
A form, a database, an API. The downstream code expects exact field names and types. Free text breaks it.
✓
Pipelines and automation
If step 2 reads the output of step 1, you need a guaranteed shape. Prose is unpredictable at scale.
!
Schema drift
The model may add extra fields or omit optional ones. Always validate the output against the schema before trusting it.
!
Not for open answers
If the response is a story or an explanation, forcing a schema just breaks the output. Use free text when a human reads it.
