Backpressure & cancellation

When the user hits cancel or a check fails, close down the work in a way that releases compute, logs the partial reply, and shows the user a tidy result.

01What is it?

A graceful cut, not a yank.

A streaming call is more than a single network request: tokens are still being generated on a server, an open socket is forwarding them, and any tool calls in flight are doing real work. Clean stopping means having a single move (a cancel signal) that tells every part to wind down in the right order: stop generating, close the connection, finish or roll back the tool call, save the partial answer for review, and tell the user exactly where things ended. Done well, the user feels they pressed stop and the system listened. Done badly, the model keeps generating in the background and you keep paying for tokens nobody will read.

03Where it fits

How it sits next to nearby ideas.

What it does
Turns a sudden cut into an orderly close: stop the work, free the resources, save what was sent, and tell the user where things ended.
Pairs with
Pairs with the quality and safety checks: when either fires, the system needs a clean way to act on the verdict. Pairs with charging logic so the bill matches what shipped.
Not this
It is not the same as a hard timeout. A timeout is a deadline. This is a planned shutdown sequence triggered by a button or a check.
04When it matters

When to reach for it.

  • Any chat or voice product with a visible stop button.
  • Long-running agent runs where cost climbs fast and a bad turn must be cut.
  • Multi-step flows where a tool call is in flight and abandoning it would leave state in a strange place.
