Cascading

Try a cheap, fast model first. Only call a stronger, pricier one if the cheap answer is not good enough.

01What is it?

Cheap first, expensive only if needed.

Each request starts at the cheapest model tier and escalates to a more capable one only if the answer fails a quality check.

03Where it fits

How it sits with nearby ideas.

Pairs with
Needs a quality check at each step. That check can be a confidence score, a judge model, or a simple rule (output format valid, length acceptable).
Compare to
Confidence-based routing decides up front which model to call. Cascading runs the cheap one, then escalates if the result is weak.
04When it matters

When to reach for it.

  • Most queries are easy and a small model handles them fine.
  • Cost per call adds up at scale and you want to spend the big model only where it earns it.
  • A clear pass/fail check exists for the cheap answer (schema valid, confidence above 0.8, judge says yes).
