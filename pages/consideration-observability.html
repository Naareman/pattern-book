Observability & Debuggability

Being able to see what the AI did and why, like a flight recorder for every answer.

01The Idea

What Is It?

When an AI answers a question, it does many things: it searches, it thinks, it calls tools, it waits for results. Observability means recording all of that, step by step, so you can look back and see exactly what happened and how long each part took. Without it, when something breaks or goes slow, you are flying blind.

02See It Work

Expand the Trace.

The AI just answered a question. Tap the answer to open the trace (the saved record of every step) and watch each step light up with its timing.

Receive request +0 ms
User message arrived. Logged query ID, timestamp, user context.
Retrieve context +120 ms
Looked up 4 documents. Nothing was saved from a previous search, so a fresh lookup ran.
Asked the AI +950 ms
Sent a question (412 tokens, meaning roughly 412 word-pieces; a token is a small chunk the AI works in). Got back a 38-token answer.
Slow: this was the slow step. 950 ms of 1400 ms total.
Return answer +1400 ms
Response streamed to user. Total: 1.4 s end-to-end. Logged to trace store.
Full trace recorded. Asking the AI was the bottleneck: 68% of total time. You now know where to optimize.
03A Real Example

When It Saves You.

A legal AI assistant starts giving one wrong citation in every twenty answers. Users complain. Without observability, the team has no idea which step failed: was the retrieval returning the wrong documents? Did the model hallucinate? Was a saved result from days ago being served instead of a fresh one?

With traces (the saved steps for each request), they pull the failing request IDs and see in minutes: the retrieval step was pulling documents from an old index that had not been updated. A single config fix. Without the trace, they would have spent a week guessing.

04Tradeoffs

The Cost of Skipping It.

lowhigh
Storage cost
Latency added
Debug time saved
Privacy risk
Traces are cheap to store and add almost no latency when done async. The privacy risk is real: logs can contain user data, so scrub or encrypt them. The payoff, when something goes wrong, is enormous.
05What This Covers

Inside C4.

Applies to: every system in production.
Axis: how to explain what the system did after the fact.

Observability & Debuggability is a discipline, not a mechanism. The hooks that actually emit traces (the raw recordings) belong to Serving Infrastructure (L0). This crosscut is the thinking framework for what to record, how to read it, and how to act on it.
