Artifact-lineage tracking

Pin a model, a prompt, an index, and an eval suite together as one named bundle so anyone can rebuild that exact state later.

01The idea

What is it?

Artifact-lineage tracking records exactly which version of every component was running at any moment as a single named bundle, so the system's state on any past date can be rebuilt from that record.

02An example

One release, four pins.

A release tag bundles every artifact together. Tap any row to see what is pinned.

release@2026-05-27
support-bot, production
M
Model
support-bot@v8
P
Prompt
prompt@v23
I
Search index
index@v13
E
Eval suite
eval-suite@v4
support-bot@v8: trained on corpus@v3 plus the latest feedback rows. Without pinning the model, a rebuild a year from now would have no idea which trained file was actually live today.
03Where it fits

Where it sits in the flow.

Each version page on its own (model, prompt, index, eval suite) saves one artifact. Lineage tracking ties them together as one bundle so the whole system's state at a moment in time has a single name.
04When it matters

When to care about it.

  • An incident review asks: "what exactly was running when this broke?"
  • You need to reproduce a result months later for a customer, an auditor, or a paper.
  • Several teams ship parts of the same system and you need one place that says which versions go together.
