Data & Artifact Lifecycle

Everything AI systems are built from: the data they learn and look things up in, and the versioned artifacts (like prompts and model files) that define how they behave at runtime.

01The Idea

What is it?

Before any AI can answer a question, four things have to exist. First, training data: the enormous pile of text the model read to learn how language works. Second, documents: the specific files or web pages you give it to look things up in. Third, embeddings (number-lists that encode meaning, so similar ideas sit close together): every piece of text turned into a list of numbers so that "find the most relevant paragraph" is fast. Fourth, weights: the actual trained model file, billions of numbers that encode everything it learned. Every other layer in this book sits on top of these four.

03A Real Example

How it fits in practice.

A company wants to let employees ask questions about internal policy documents.

Documents
200 PDF policy files.
The raw source of truth. Text is extracted and cleaned.
→
Embeddings
Each paragraph becomes a number-list and is stored in a vector database.
Enables fast "find the most similar chunk" search.
→
Weights
A pre-trained language model reads the retrieved paragraphs and answers.
The model's knowledge comes from its training data; the documents supply the specifics.
04Inside This Layer

Every category in L−1.

Axis: the lifecycle stage of the artifacts that feed and define the system.
Data
Collection & Sourcing
Finding and pulling in the raw text, images, or signals the system will learn from or look things up in.
Labeling & Annotation
Human (or automated) tagging of examples so the model can learn what "correct" looks like.
Data Quality & Deduplication
Filtering out noise, duplicates, and low-quality samples so the model trains on signal, not garbage.
Synthetic Data Generation
Creating artificial training examples (often from another AI) when real data is scarce or expensive to label.
Versioning & Lineage
Tracking which version of a dataset produced which model, so you can reproduce or audit any result.
PII Scrubbing & Redaction
Removing personally identifiable information (PII: names, emails, phone numbers, and similar private details) before data is used for training or retrieval.
Retention & Deletion Policies
Rules for how long data is kept and when it must be purged, often driven by regulation or user consent.
Feedback Data Pipelines
Capturing user thumbs-up/down, corrections, or behavioral signals and routing them back into future training runs.
Deployable Artifacts
Prompt Versioning
Treating the text instructions you send the AI (the prompt) like code: saving versions, comparing them, and rolling back when a change makes things worse.
Model Versioning
Managing which trained model checkpoint is live in production, so upgrades and rollbacks are deliberate and traceable.
Eval-Suite Versioning
Versioning the set of test questions and scoring rubrics used to grade the AI, so benchmark scores are comparable across time.
Retrieval-Index Versioning
Tracking when the search index (the database of embeddings the AI queries) was last rebuilt and from which data snapshot.
Cache-Contents Lifecycle
Managing what is stored in the response cache: when entries are populated, when they expire, and how the schema evolves without breaking old entries.
Artifact-Lineage Tracking
Recording the full chain of custody from raw data through processed dataset through model through deployment, so any output can be traced to its origin.
Rollback & Roll-Forward
The ability to safely switch any deployed artifact (prompt, model, index) back to a prior version or forward to a new one without downtime.
Filing rule: Data consumed by training or retrieval belongs in the Data sub-axis. A config that defines runtime behavior (like a prompt or model version) belongs in Deployable Artifacts. The runtime reads the artifact (that is L0); the artifact's lifecycle lives here.
