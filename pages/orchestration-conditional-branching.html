Conditional branching

The path through your system depends on what the model finds at runtime. Different inputs take different routes.

01The Idea

A fork in the road.

The system evaluates a condition and follows exactly one branch, so two requests starting in the same place can take entirely different routes.

02An Example

Confident or not?

Answer drafted
confidence >= 0.8?
→
Yes → ship answer to user
No → ask a clarifying question
High confidence path: the draft passes the check, so the system ships it to the user without bothering them for more info.
03Where It Fits

How it sits next to other shapes.

Sits next to
Routers and iterative loops. A router branches once at the very start. A loop branches every round. Conditional branching is the general "pick a path based on what just happened" idea behind both.
Not the same as
A sequential pipeline. A pipeline always runs the same steps in the same order. Branching is the moment your system says "it depends."
04When It Matters

When to reach for it.

  • Some inputs need more work than others (low-confidence answers need a second look; risky actions need approval).
  • You want a safety net: if the check fails, take the safe branch instead of the expensive one.
  • You want to keep the simple path fast and only pay for the heavy path when it is needed.
