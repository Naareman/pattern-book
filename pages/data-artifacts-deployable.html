The versioned files

The saved files the AI runs on: prompts, model versions, search indexes, and caches, and how you version them and safely swap them.

Versioning what you ship

Want to treat your instructions to the AI like code: save versions and roll back when something breaks? → Prompt versioning↗
Want to control which trained model checkpoint is live and make upgrades deliberate? → Model versioning↗
Want your test suite to be versioned so benchmark scores are comparable over time? → Eval-suite versioning↗
Want to track when your search index was last rebuilt and from which data snapshot? → Retrieval-index versioning↗

Managing what lives in the cache

Want to control what gets cached, when entries expire, and how the schema evolves without breaking old entries? → Cache-contents lifecycle↗

Tracing and recovering from changes

Want a full chain of custody from raw data through model through deployment so any output can be traced to its origin? → Artifact-lineage tracking↗
Want to switch any live artifact (prompt, model, index) back to a prior version or forward to a new one without downtime? → Rollback and roll-forward↗
