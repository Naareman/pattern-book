Re-running a past request exactly as it happened

Replay loads the saved pieces of a past request (the prompt, the documents, the model version, the settings) and runs them again so you can pick the request apart safely.

01What It Is

Press play on a frozen request.

To replay a request, the system pins down every input that shaped the original answer: the exact prompt, the documents that were pulled in, the model name and version, the temperature, the system message, and the tool results. With those pinned inputs, the same request can be run again in a sandbox: against the same model to see if it answers the same way, or against a new prompt or a new model to see if the change would have helped. Replay turns a one-off mystery into something you can poke at as long as you want.

03Where It Fits

How it relates to nearby ideas.

What it is
A safe sandbox for running an old request again. The trace tells the story. Replay lets you live inside that story and try changes.
Sits next to
Pairs with tracing (the source of the pinned inputs), versioning of prompts and indexes (so old pieces still exist), and evaluation (judging the new answer against the old one).
04When It Matters

When to reach for it.

  • A new prompt or new model is about to ship and you want to see how the old failing requests would have gone.
  • A single weird answer needs to be picked apart, and you want to test a fix without bothering the real user.
  • You want to build a regression set: a folder of past failures the next change must answer correctly.

Sources
