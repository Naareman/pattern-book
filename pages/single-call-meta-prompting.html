Meta-Prompting

Use the model to help write or improve the prompt itself, so you start with a stronger instruction than you could write alone.

01What It Is

The prompt that writes the prompt.

Meta-prompting means asking a language model to generate or refine a prompt that will then be used in a downstream call. You describe the task you need, the audience, the constraints, and the failure modes you want to avoid. The model produces a structured instruction set. You review, adjust, and then use that instruction set as your actual system prompt. This is especially useful when you know what output you want but struggle to articulate the precise instructions that would reliably produce it.

02An Example

From description to ready prompt.

1
You send (the meta call)
Write a system prompt for a contract review assistant. It should: extract key obligations, flag missing standard clauses, warn about unusual terms, and refuse to give legal advice. Output must be plain English for non-lawyers.
↓
2
Model returns (the generated prompt)
You are a contract reading assistant. When the user shares a contract, do the following: (1) List the main obligations on each party in plain English. (2) Flag any of these standard clauses if missing: indemnification, limitation of liability, governing law, termination notice. (3) Highlight any clause that seems unusual or one-sided. Do not give legal advice or predict outcomes. End with: "Review with a qualified lawyer before signing."
↓
3
You review, tweak, deploy
The generated prompt becomes your system prompt. You saved 30 minutes of trial-and-error iteration.
03Where It Fits

Its place in the taxonomy.

L4
Home layer
Input Shape sub-axis. The output of meta-prompting is the prompt text that enters the downstream model call. The technique shapes that input.
L−1
Cross-reference
The generated prompt becomes a Deployable Artifact. Versioning and storage of it are L−1 concerns. Meta-prompting is how you author it; L−1 is how you manage it after.
Filing rule: The meta call itself is a separate model call, but the pattern's purpose is to produce a better input for the production call. The technique is filed under Input Shape because that is what it affects.
04When It Matters

Who needs this.

Teams that ship many different AI features without a dedicated prompt engineer. Product managers and domain experts who know what they want but find prompt writing unintuitive. Also valuable early in a project when you are exploring what a good prompt for a new task even looks like, before committing to manual iteration.
