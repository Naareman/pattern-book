Modality-specific safety

A safety filter that only reads words will miss harm carried in a photo or a voice clip. Each input shape needs its own check before it reaches the model.

01What Is It?

A filter for every shape.

Multimodal safety runs a separate safety check for each input type (text, image, audio) because text-only filters go blind the moment an image or audio clip enters the system, and harmful content can hide inside any of them.

02An Example

Three inputs, three checks.

text
Words asking for harm
Standard text classifier scans the prompt and flags requests for violence, abuse, or other banned content.
image
Pictures of harm, or text hidden in pictures
An image classifier catches unsafe scenes. A separate text reader pulls any writing inside the image so the text filter can see it too.
audio
Spoken harm, or tone that masks it
A transcriber turns speech into text for the standard filter. An audio model can also flag screams, threats, or wake words the transcript would lose.
The work: each input shape gets the right filter, the results are pooled, and the call is blocked or allowed based on the combined view.
03Where It Fits

How it sits next to nearby ideas.

Extends
Standard text safety: the same harm taxonomy applies, but each shape needs its own detector to spot it.
Pairs with
Grounding. Grounding asks "did the model invent this?"; safety asks "would this content cause harm?" Both run on the same inputs and outputs.
04When It Matters

When to think about it.

  • The product accepts images or audio from end users and any input could be harmful.
  • Bad actors try to bypass text filters by hiding the request inside an image (the screenshot trick).
  • The model generates images or speech, and those outputs need their own review before they reach a viewer.
