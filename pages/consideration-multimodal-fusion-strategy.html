Decide when to blend the inputs

When a user sends an image and text together, choose whether the model sees them mixed from the start or whether each one is summarised on its own first.

01What Is It?

Mix early or mix late.

Two inputs of different shapes (say, a photo plus a sentence) can be combined at different moments. Early blending hands both to the same model in the same call, so the model reasons across them together. Late blending runs each input through its own step first, then passes the two summaries to a final step that joins them. Early keeps more nuance. Late keeps each step small, simple, and easier to swap.

02An Example

A rash photo plus a question.

Path
photo + question → one multimodal model → answer
The model sees the redness and the question together. It can match a phrase like "since Tuesday" to a faint mark in the image. Richer reasoning, higher cost per call.
Path
photo → image describer → description
question → kept as text
description + question → text model → answer
Each input becomes plain text first, then a regular language model combines them. Cheaper, easier to swap parts, but any image detail the describer skipped is gone for good.
03Where It Fits

How it sits next to nearby choices.

Follows from
Once you have picked the path for each input on its own, this question is what to do when several inputs arrive together.
Drives
The blending moment sets cost, speed, and how easily you can swap one part later. It is the largest single lever for a multi-input flow.
04When It Matters

When to think about it.

  • The answer depends on the link between the inputs, not just each one separately.
  • You want to swap one piece (the image describer, the language model) without rebuilding the whole flow.
  • Cost or latency is tight and one of the inputs is small enough to summarise cheaply on its own.
