Prompt Versioning

Treat the instructions you send the AI like code: save every version, track what changed, and roll back instantly when a new version breaks things.

01What it is

What is it?

A prompt registry stores every draft of your system prompt with a version tag, a timestamp, and a change note. Teams deploy a specific pinned version to production rather than editing the live prompt in place. When a new version regresses quality (worse answers, a broken format, missed edge cases), the registry makes recovery a one-step operation: pin back to the last known-good version and the system is restored immediately, with no code deploy needed.

03Where it fits

How it relates to nearby ideas.

What it manages
A prompt is a saved file that shapes how the system behaves. This pattern is about its whole life: writing it, picking which version is live, and rolling back.
At run time
When a request comes in, the system reads whichever prompt version is currently live. That reading at run time is a separate concern from keeping the version history.
Pairs with
The tests that catch a bad new version belong with evaluation. Versioning is how you save and swap prompts; evaluation is how you know which version is good.
04When it matters

When to reach for it.

  • Any team that edits prompts in production.
  • More than one person touches the system prompt, so you need to see what changed and when.
  • You ship prompt changes often and want a quick, code-free way to undo a bad one.
