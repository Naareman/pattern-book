Generator-critic pairs

One call writes a draft. A second call critiques it. The first call uses that feedback to rewrite. Repeat until the critic is happy.

01What is it?

Draft, critique, redraft.

A generator produces an answer, a critic identifies specific problems, and the generator revises, with the loop stopping once the critic signals the output is good enough.

02An Example

Two rounds, cleaner code.

Task
Write a function that returns the median of a list.
Generator
Draft: Sort the list, return the middle item.
Critic
Feedback: Fails on even-length lists. Empty list crashes. Add tests.
Generator
Redraft: Sort, average the two middle items when even, return None on empty. Three tests added.
Critic
Feedback: All three cases pass. Good to ship.
Ship the round 2 answer
The critic uses a checklist (edge cases, tests, format). Most loops settle in one or two rounds. Capping the rounds keeps cost predictable.
03Where it fits

How it sits with nearby ideas.

Compare to
Plain verification stops after the judge speaks. Generator-critic loops feed the critique back so the answer gets fixed, not just rated.
Pairs with
Works best when the critic has something solid to point at: a test suite, a linter, a spec, or a checklist. Vague critique leads to vague rewrites.
04When it matters

When to reach for it.

  • The task has a clear standard for done (tests pass, schema valid, rubric met).
  • The first draft is usually close but misses a few details (code, structured writing, formatting).
  • You can cap the loop at 2 or 3 rounds so cost stays bounded.
