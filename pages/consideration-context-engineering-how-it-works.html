Context Engineering

Decide what loads into the model's context window: what to keep, what to fetch, what to compress, what to isolate.

01The Idea

What is it?

The context window is the model's working memory: like RAM in a computer, it holds only what fits right now, so every call is a choice about what to load, what to discard, and what to keep somewhere else for later.

03A Real Example

A support chat with 200 messages.

WRITE After each turn, key facts (user's plan tier, past errors, their name) are saved to a user memory store so they don't have to repeat themselves next session.
SELECT At call time, only the last 10 messages plus the 3 most relevant past tickets are retrieved. The other 190 messages stay in storage, not in context.
COMPRESS The older retrieved messages are summarized into a single paragraph. The full text is dropped. The model gets the meaning without the tokens.
ISOLATE When the user pastes a long error log, a sub-agent processes it in its own fresh context. Only the diagnosis comes back. The raw log never touches the main conversation context.
04Tradeoffs

The price you pay.

lowhigh
More selection: retrieval cost
More compression: info loss risk
More isolation: orchestration overhead
No strategy: token cost spiral
The four verbs work together. Write saves retrieval cost by keeping facts close. Compress keeps selection cost low. Isolate keeps the main context clean so selection stays accurate.
