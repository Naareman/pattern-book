Eval-suite versioning

Save the test set itself with a version tag so two scores are only compared when they were measured by the same ruler.

01The idea

What is it?

Eval-suite versioning freezes the test set at a tagged version so that any two scores can only be compared when they were measured by the same questions.

02An example

Same model, two suites, two scores.

The model did not change. The suite did. Look at the gap before you celebrate or panic.

eval-suite@v3
Last month's suite
0.87
200 questions
No hard edge cases yet. Easy questions made the score look high.
eval-suite@v4
This month's suite
0.74
240 questions
40 new hard cases added. Same model now looks worse, but it is the test that got tougher.
Without a version tag, the team would have thought the model got worse. The tag tells them the ruler changed. They re-run v8 of the model against eval-suite@v4 to compare apples to apples.
03Where it fits

Where it sits in the flow.

Every score is saved alongside both the model version and the eval-suite version that produced it. Comparisons only make sense when those two tags line up across runs.
04When it matters

When to care about it.

  • You track model quality over time and want to trust the trend line.
  • You add new tests as you find new failure modes, so the suite naturally grows.
  • Two teams report numbers from "the eval set" and you suspect they mean different things.
