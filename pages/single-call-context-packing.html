Context Packing

Put everything the model needs into one prompt when the data fits. No retrieval, no multi-turn loop: one call, full context, one answer.

01What It Is

Load the whole corpus.

Context packing means placing all relevant documents, history, and instructions directly into one prompt and sending it in a single call, skipping a separate retrieval step.

02An Example

Anatomy of a packed prompt.

128k token context window 92k used
System prompt + instructions
~800 tok
All 38 product spec PDFs (packed directly)
~88k tok
Conversation history (last 10 turns)
~3k tok
User's current question
~80 tok
No retrieval pipeline. No chunking. No embedding model. The model reads every spec on every call. Simple to build, expensive to scale: each call costs the full token count regardless of what the user actually asks about.
03Where It Fits

Where it fits.

Home
A way of writing your prompt: deciding what text goes into it. The whole idea is about building the input for one call to one model.
Replaces
When everything fits in the prompt, packing removes the need for a separate search step (retrieval) altogether. You hand the model the whole set of documents at once instead of fetching the relevant parts on demand.
Cross-reference
Choosing between packing everything in and using retrieval (RAG) comes down to cost, speed, and how much the model can recall. That is a cost-and-performance call.
In short: the information goes into one prompt, read by one call. If a separate search step picked what to include, that step would be a different layer; packing the result still lives here.
04When It Matters

When to reach for it.

  • Your material is small and stable: a fixed product list, a set of policy docs, a small codebase.
  • It is the fastest way to a working prototype, since there is no search step to build.
  • Switch to retrieval (RAG) once the cost per call adds up or there is too much to fit.
