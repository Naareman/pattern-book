Layer 2

Serving & infrastructure

How the AI runs fast and stays working when everyone asks at once.

01The Idea

What is it?

When you ask an AI a question, the words go to a server with powerful GPUs that run the model. To handle thousands of people at once, three tricks work together: requests get batched (grouped so the GPU works on many at once), popular answers are cached (stored so the GPU skips the work entirely), and traffic is split across multiple machines so no single server gets overwhelmed.

03A real example

Where you've felt this.

⚡ChatGPT answers fast even when millions use it
Tap to see why
OpenAI runs thousands of GPUs in parallel and batches concurrent requests together. Your prompt usually shares a GPU pass with dozens of other users' prompts, so the cost per answer stays low and the wait stays short.
💾Asking the same question twice feels instant the second time
Tap to see why
Many inference providers cache the output for common or identical prompts. The second request hits the cache and returns in milliseconds — the GPU never runs at all.
🌍AI apps still work during a datacenter outage
Tap to see why
Traffic is split across multiple servers and regions. A load balancer watches which machines are healthy and reroutes requests around any that go down — so the service stays up even when hardware fails.
04Tradeoffs

What each trick costs.

These three techniques work together. Caching saves the most time for repeated questions. Batching saves money for unique ones. Multiple servers mean users never notice when a machine goes down.
