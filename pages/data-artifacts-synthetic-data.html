Synthetic data generation

Using a model to invent extra examples when real ones are scarce, sensitive, or expensive to collect.

01The idea

What is it?

Sometimes you do not have enough real examples to train or test on. Synthetic data generation uses a model to produce new examples from a few seeds: rephrased questions, made-up customer cases, simulated logs. The generated set is then mixed with the real data or used on its own.

02An example

One seed, three variants.

A team has one customer question. They use a model to spin up more, so the bot sees the same intent worded different ways. Tap to generate.

Real seed
"How do I cancel my subscription?"
↓ Ask a model
syn-1"I want to stop my plan, where do I do that?"
syn-2"Can you walk me through ending my membership?"
syn-3"I no longer want to be billed, please cancel."
03Where it fits

Where it sits in the flow.

Synthetic data sits alongside collected data. It is added to the same dataset, but it is tagged as generated so you can always tell which examples came from real users and which a model wrote.
04When it matters

When to care about it.

  • Real examples are rare (a new product, an edge case, a quiet language).
  • Real examples are sensitive, so you cannot use them directly (medical, financial).
  • You need to cover a long tail of phrasings or scenarios cheaply.
