Compensating Actions and Rollback

When step 3 fails, you cannot just press undo on step 1 or step 2. You have to run a real, opposite action: refund the charge, cancel the booking, delete the calendar invite.

01What is it?

An undo that is its own action.

A compensating action is a second operation that logically reverses an already-completed step when a later step in the workflow fails.

02An Example

A trip booking that can be unwound.

Each forward step paired with the action that undoes it.
Forward step
If we need to undo
1
DoBook flight
UndoCancel flight reservation
2
DoReserve hotel
UndoRelease hotel hold
3
DoCharge card
UndoRefund charge
Step 3 fails. Run "release hotel hold" then "cancel flight reservation" in reverse order. The user ends up where they started, not stuck mid-trip.
03Where It Fits

Where it sits.

Builds on
External action. You only need compensating actions because the steps you took were real changes to the outside world.
Not the same as
A database rollback. That works because nothing was visible yet. Once an email is sent, your only "undo" is a retraction email.
Pairs with
Multi-step transactions, which orchestrate the forward steps and their compensations as one unit.
04When It Matters

When to reach for it.

  • A workflow touches more than one outside system (payments, calendars, inventory) and any one of them might fail.
  • A half-completed sequence would be worse than no sequence at all: a paid-for trip with no hotel, an issued refund with no order.
  • You need to be able to recover cleanly from a partial failure without manual cleanup by a human later.
