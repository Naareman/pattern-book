Approval Gates

Before the agent does something risky, it stops and asks a human to say yes. The agent waits, the human decides, the action happens (or doesn't).

01What is it?

A human in the loop.

An approval gate is a planned pause where the agent prepares the action and shows it to a human before running it, reserved for the steps where a mistake would be costly.

02An Example

Agent pauses before spending.

Agent
Drafts $4,800 vendor payment
→
Gate
Human reviews and approves
→
Action
Payment is sent
Where the gate triggers. A rule decides when to pause, not the agent's mood:
over $1,000 first-time vendor change to existing customer record message to an external party
03Where It Fits

Where it sits.

Two halves
The runtime pause and resume (the orchestration side) and the screen the human uses to approve (the user interface side). This page is about the pause itself.
Pairs with
External action. The gate exists because the next step is a real-world change worth a second pair of eyes.
Not the same as
A sandbox. A sandbox lets a risky action run safely in a contained space. A gate refuses to let it run at all until a person says yes.
04When It Matters

When to reach for it.

  • The action would be expensive or embarrassing to reverse: large payments, mass emails, customer-visible changes.
  • Rules or compliance require a human signature for certain decisions (finance, legal, health).
  • Early in a rollout, when you want to ship the agent but keep a person watching the high-stakes calls.
