Slimming the model to fit

Store the same model using fewer bits per number. It shrinks on disk, fits a smaller GPU, and runs faster, with a small drop in quality.

01What is it?

Same model, less precise numbers.

Quantization rounds the model's billions of numbers from a high-precision form to a coarser one (often from 16 bits down to 8 or 4). The shape and behaviour stay close, but the file is smaller and each calculation is quicker.

What changes: the model file shrinks, it now fits on smaller (cheaper) hardware, and each call uses less memory bandwidth, so answers come out faster. Quality drops a little, more on hard tasks than easy ones.
03Where it fits

Where it sits.

Common uses
Done once when the model is packaged, then loaded by the serving engine. Standard in open models published on Hugging Face and in on-device deployments.
Pairs with
Smart memory layout and answering many at once. A slimmer model leaves more memory free for users; the layout and batching turn that into more concurrent traffic.
Different from
Picking a different smaller model. Quantization keeps the same model and shrinks its numbers; picking a smaller model swaps in a different brain.
04When it matters

When to reach for it.

  • You need the model to run on smaller, cheaper, or fewer GPUs.
  • You want to ship the model on a laptop, phone, or edge device.
  • A small quality drop is acceptable for the task, and you can test which precision level keeps quality high enough.
