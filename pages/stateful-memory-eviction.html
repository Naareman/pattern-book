Memory eviction & forgetting

Some notes age out. Some get replaced by newer truths. Some you ask the system to forget. Forgetting on purpose is part of the design.

01What it is

Throw a note away on purpose.

Memory eviction is a rule that removes an entry from the store when it becomes stale, gets superseded, the user requests deletion, or the store needs to make room for newer entries.

03Where it fits

How it sits next to nearby ideas.

Sits next to
Shrinking. Shrinking turns many notes into a shorter summary. Dropping throws notes away. Most systems do both: shrink first, then drop the leftovers.
Why it matters legally
"Delete my data" requests under rules like GDPR mean dropping has to be reliable, traceable, and complete. Not just hiding the note from the prompt.
04When it matters

When to reach for it.

  • A user asks the model to forget a fact and you need to honour that everywhere it was stored.
  • The model keeps bringing up old, stale information that no longer holds.
  • Storage cost or compliance rules cap how much you can keep per user.
