Shared Workspace

A common place agents can read from and write to, so each one builds on what the others have already done.

01What It Is

One board, many hands.

A shared workspace is a single storage area every agent can read and write, so agents coordinate by posting and reading findings rather than messaging each other directly.

02An Example

Tap an agent to see what it adds.

Research project: market scan for Acme /workspace/acme/
Workspace contents
researcher.md
15 competitor names, 3 pricing tables, 8 product pages
analyst.md
3 themes: bundling, freemium, enterprise tier
draft_v1.md
2-page memo, 4 charts, draft recommendation
Researcher writes raw findings to the board. It does not need to know who reads them next.
No direct messages. Each agent reads what is on the board and adds its own piece. The order can change, work can pause and resume, and a new agent can join later by reading what is already there.
03Where It Fits

How it relates to nearby ideas.

What it is
A meeting place for agents, not a way of talking. It says where things live so anyone can pick them up. The talking format itself is a separate concern.
Sits next to
Pairs well with an agent-to-agent protocol (how they talk), identity (who is allowed to write to which folder), and memory (what carries across sessions).
04When It Matters

When to reach for it.

  • Several agents work on the same project and you want each one to build on the others' output.
  • Work happens in stages, can pause, and may be picked up later by a different agent.
  • You need a single audit trail of what was written and by whom across the whole run.
