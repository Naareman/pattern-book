Prompt Compression

Shrink long prompts before sending them. Fewer tokens means lower cost, lower latency, and less lost-in-the-middle noise.

01What It Is

Say the same thing with fewer tokens.

Prompt compression reduces the token count of a prompt while preserving the meaning the model needs, stripping length without stripping signal.

02An Example

A bloated system prompt, trimmed.

Support bot system prompt
Before (verbose)
You are an AI assistant that has been designed and created to help users of our company's software product answer their questions and resolve their issues. You should always be polite and professional in your responses. When a user asks you a question, please make sure that you take the time to understand what they are asking before providing a response. You should only answer questions that are related to our product. If a user asks about something that is outside the scope of our product, please let them know that you are unable to help with that particular topic and suggest that they contact the relevant support team.
~90 tokens
After (compressed)
You are a support assistant for our software product. Be professional. Answer only product questions. For anything out of scope, say so and direct users to the relevant team.
~32 tokens
64% fewer tokens. Same coverage, no meaning lost.
03Where It Fits

How it relates to nearby ideas.

What it shapes
It changes the text that goes into the model call. Whether you trim it by hand or use a small model to do it, the result is a shorter prompt for the same single call.
The tradeoff
Deciding whether to compress, and how hard, is a cost question. Compression saves money but can drop details if you cut too much.
04When It Matters

When to reach for it.

  • High-volume apps where the prompt length is a real cost line: support bots, code review, summarization pipelines.
  • Speed-sensitive apps where the time to the first word matters.
  • When prompts include user-supplied or retrieved text you cannot trim by hand, so you automate it.
