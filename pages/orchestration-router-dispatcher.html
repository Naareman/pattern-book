Router / dispatcher

One entry point reads the request, decides what kind it is, and sends it to the right specialist.

01The Idea

A receptionist for requests.

The first call only does one thing: read the incoming request and pick which downstream handler should answer it. Each handler can have its own prompt, its own model, even its own tools. The router itself never tries to answer.

02An Example

Three questions, three desks.

Request
Reset my password
→
Router picks
Technical support
Why: contains an account action ("reset"), routed to the support team's prompt with access to the account tools.
03Where It Fits

How it sits next to other shapes.

Sits next to
Hierarchical planning. A router picks one specialist for the whole request; a planner breaks a request into many steps and hands each to a different worker.
Not the same as
A classification model. A router can be any decider (a model call, a rule, a keyword match). The point is the shape: one front door, many back rooms.
04When It Matters

When to reach for it.

  • Requests fall into a few clear types and each type needs its own prompt, model, or tools.
  • You want a small cheap model up front and the expensive one only when the request truly needs it.
  • One mega-prompt that tries to handle everything is getting fragile.
