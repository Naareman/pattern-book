Swarm

A small group of peer agents that pass the conversation between themselves based on what the task needs next. No supervisor, no hierarchy, no fixed roles.

Default in 2026 · Updated June
OpenAI Swarm is deprecated; the OpenAI Agents SDK Handoffs API is its spiritual successor. Reach for peer-to-peer only when no single agent has authority and roles shift dynamically. Mostly research, rarely production this year.
01The Idea

What is it?

A Swarm is a group of agents who talk to each other as peers, not as boss and reports. Whoever holds the conversation looks at what the task needs next and hands it off to whichever peer can do that next thing. The handoff is the structure. No agent has lasting authority. Roles shift turn by turn.

03A Real Example

Who actually ships this.

Honest receipts: the foundational reference is deprecated, the successor is well-supported but young, and production usage is concentrated in research labs and orchestration demos rather than user-facing apps.

OpenAI · Swarmdeprecated
The reference implementation that defined the recipe in 2024: agents declare handoff functions, the framework routes turn-by-turn with no central manager. Maintained as an educational library but no longer recommended for new builds.
github.com/openai/swarm
OpenAI · Agents SDK Handoffssuccessor
The production-supported spiritual successor. handoff() primitives let agents transfer the conversation to a peer with full context. Comes with tracing, guardrails, and a Python-first API.
openai.github.io/openai-agents-python
CrewAI · Flows for peer mode
Event-driven flows let agents react to each other's outputs without a manager. The closest production-grade swarm pattern in the CrewAI stack: declarative routing instead of a hierarchical process.
docs.crewai.com/concepts/flows
Anthropic · MCP federationresearch-ish
Model Context Protocol is the substrate that lets independent agents discover and call each other's capabilities. Not a swarm framework by itself, but the open protocol that makes peer-to-peer agent topologies plausible across vendors.
modelcontextprotocol.io

No supervisor means no single place to fix a runaway loop, drop a bad handoff, or override a dumb decision. You gain adaptability and lose the safety net that hierarchy provides.
05Patterns It Uses

Which layers do the work.

Agent-to-agent protocols: peers speak directly, not through a manager Capability negotiation: whoever holds the conversation picks the next peer based on declared skills Shared workspace: the conversation history is the only common state across peers Router / dispatcher: routing logic lives inside each peer, not in a central node Agent identity: each peer has a stable role declaration that others can discover and hand off to
Decomposes into: at Layer 5, this recipe is coordination with no supervisor, plus dynamic role transitions on every turn. Roles are still declared statically, but who holds the conversation is decided turn-by-turn by the holder, not by a fixed plan.
06When To Use

Swarm, or a shape with a boss?

Swarm is the right answer in fewer cases than it looks. Most teams default to it because it sounds futuristic, then end up rebuilding hierarchy by hand.

vs.
Supervisor / Worker
A boss agent owns the plan and tells workers what to do. Pick this when authority is fixed and you want a clear audit trail.
pick swarm when
There is no boss
No one peer can sensibly own the whole task and authority shifts based on what each turn needs. Let the holder hand off.
vs.
Multi-Agent Debate
Peers argue opposing positions to surface tradeoffs. Pick this when adversarial pressure improves the answer.
pick swarm when
Peers are collaborating
Everyone is on the same side, just with different skills. Handoffs are help, not challenge.
vs.
Hierarchical Multi-Agent
Formal levels: orchestrator, team supervisors, specialist workers. Pick this when the task is genuinely tree-shaped.
pick swarm when
Roles shift dynamically
The next move depends on what the last move uncovered, not on a pre-drawn org chart.
The honest rule. If you can name a supervisor, use one. Swarm earns its place only when no agent can credibly own the result, and you are willing to accept harder debugging in exchange for adaptability. In 2026 this is still mostly research, rarely production.
