Iterative loops

Think, act, see the result, think again. Repeat until the model has enough to answer.

01The Idea

Try a step, see, repeat.

Instead of planning all steps upfront, the model takes one action, observes the result, then decides the next step, repeating until it declares done or a safety limit stops it.

02An Example

A weather question, three rounds.

Round 1 of 3
Think User wants Paris weather tomorrow. I should look it up.
Act call_tool("weather", city="Paris", date="tomorrow")
See { "high": 18, "low": 11, "rain": true }
03Where It Fits

How it sits next to other shapes.

Sits next to
Sequential pipelines. A pipeline has its steps fixed up front; a loop decides each step at runtime based on what just happened.
Not the same as
A tool call by itself. A tool call is one action; this is the loop that decides whether to call a tool, look at the result, and call another.
04When It Matters

When to reach for it.

  • You cannot know the steps up front: research, debugging, browsing.
  • The model needs to react to what tools return (a missing record, a 404, partial data).
  • The job has a clear stopping condition: an answer found, a task done, a budget hit.
