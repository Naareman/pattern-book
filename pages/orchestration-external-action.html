External Action

When the agent uses a tool that actually changes something out in the world. Sending an email, booking a flight, posting an order: these are different from just looking things up.

01What is it?

Tools that change things.

An external action is a tool call that changes the world when it runs, unlike a read-only lookup, so it cannot be safely retried without extra care.

02An Example

Look up vs. do.

get_weather(city: "Cairo")
search_inventory(sku: "A-1024")
read_calendar(user: "nareman", date: "2026-06-01")
Calling these twice gives the same answer twice. No harm done.
send_email(to: "client@x.com", body: "...")
charge_card(card: "...4242", amount: 49.00)
book_flight(passenger: "...", flight: "MS986")
Calling these twice can send two emails, charge twice, or book the same seat twice. Each one needs a plan for retries and failures.
03Where It Fits

Where it sits.

What it is
The class of tool calls that change real-world state. The starting idea: once you have these, you need the rest of this cluster.
Not the same as
Read-only lookups (searching a database, fetching a page). Those return information without leaving a trace.
Then what
Idempotency, rollback, approval gates, sandboxing, and transactions are the safety net around external actions.
04When It Matters

When to reach for it.

  • The agent is moving from giving advice to actually doing things on the user's behalf.
  • Money, communication, or scheduling are involved, where a second click costs real money or trust.
  • You are integrating with someone else's system (a payment gateway, an email provider) where a mistake is visible to the outside world.
