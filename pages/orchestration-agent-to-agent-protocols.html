Agent-to-Agent Protocols

A shared message format so one agent (or the tool it uses) can talk to another the same way every time, even when they come from different vendors.

01What It Is

A common language between agents and tools.

An agent-to-agent protocol is a shared set of rules that lets one agent ask a tool or another agent to act and receive the reply, without either side knowing the other's internals.

MCP Model Context Protocol (Anthropic, 2024). Lets one agent talk to tools and data sources in a standard way, so any model can use any MCP-compatible tool.
A2A Agent-to-Agent protocol (Google, 2025). Lets one agent hand work to another agent, including agents built by other teams or vendors.
02An Example

Same task, shared shape.

Agent→tool server
Request the agent sends
{ "method": "tools/call", "params": { "name": "search_invoices", "arguments": { "vendor": "Acme" } } }
Reply the tool returns
{ "content": [ { "type": "text", "text": "3 invoices found..." } ] }

The model does not need to know how the tool is built. It just speaks the protocol. Swap one tool for another that speaks the same protocol and the agent keeps working.

Agent A→Agent B
Task that Agent A sends
{ "task": "draft_reply", "input": { "thread_id": "t_482" }, "reply_to": "https://a/callback" }
Status update Agent B posts back
{ "task_id": "t_482", "state": "completed", "artifact": { "draft": "Hi Acme..." } }

Two independent agents (different teams, different models) exchange tasks and results without either side knowing the other's internals.

03Where It Fits

How it relates to nearby ideas.

What it shapes
The wire format and turn-taking between two parties: caller, callee, request, reply, status. It says nothing about what the agent thinks inside one call.
Sits next to
Identity (who is calling), capability discovery (what the other side can do), and a shared workspace (where they put intermediate results) all build on top of the same protocol.
04When It Matters

When to reach for it.

  • You want to plug in tools or sub-agents from outside teams without rewriting your agent each time.
  • You expect to swap the underlying model later and want the tools to keep working.
  • You have several specialist agents (research, drafting, review) that should hand work to each other in a way you can log and audit.
