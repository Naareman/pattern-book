Model versioning

Treat each trained model like a saved file: pin a version to production, keep the old ones, and swap them safely.

01The idea

What is it?

A trained model is a big file (weights and settings) that took hours or days to produce. Model versioning saves every trained model with a tag, a date, and what it was trained on. The system pins a specific version to production rather than overwriting the live one, so older versions can always be brought back.

03Where it fits

Where it sits in the flow.

The model registry sits between training and production. Training runs produce new versions. The registry stores them all. Production picks one to serve. Swapping versions is a pointer change, not a file copy.
04When it matters

When to care about it.

  • You ship more than one model into production over time.
  • You need to roll back fast when a new release behaves worse than the last one.
  • Two teams or two products share the same model and need to agree on which version is live.
