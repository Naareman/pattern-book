Multimodal

How to reason about systems that handle images, audio, or video alongside text. Text-only systems can skip this consideration.

01The Idea

What is it?

A multimodal model can read more than one kind of input. Not just words, but also images, audio, and video. The trick is that everything, a photo, a spoken word, a block of text, gets converted into the same kind of unit before the model ever sees it. That unit is called a token (a token is a small piece the AI works in: roughly a word, or a slice of an image or sound). One unified stream. One model.

03A Real Example

In the wild.

"Here is a photo of a rash. Is it something I should see a doctor about?"

The model receives an image and a text question together. It encodes the photo into patch tokens, mixes them with the word tokens, and reasons across both at once to give a medically grounded answer.

"Transcribe this meeting recording and summarize the action items."

Audio frames are encoded into spectrogram tokens. The model reads those tokens alongside any text prompt, then writes the transcript and summary as a single pass, no separate speech-to-text step needed.

"Watch this 30-second product demo and write the key selling points."

Video is sampled into frames; each frame is encoded like an image. Those frame tokens are laid out in time order, so the model sees what changed and when, then writes a narrative across the full clip.

04Tradeoffs

The price you pay.

Error modes
A high-res image can add thousands of tokens to a single request. Video multiplies that by the number of frames sampled. And misaligned encoders (trained separately) can cause the model to "hallucinate" objects that are not there. Multimodal is powerful, but every extra modality is extra cost, weight, and a new class of mistake.
05What This Covers

The disciplines inside C6.

⚠︎
Applies to: only systems that handle images, audio, or video. Text-only systems can skip this consideration entirely.
Axis: how to reason about systems that span text, vision, audio, or mixed modalities.

Choosing and combining modalities

Modality selection Pick which modality to use for a task: OCR-then-reason versus native vision, speech-to-text versus end-to-end audio.
Cross-modal grounding Keep the model's output faithfully tied to what it saw or heard, not a hallucinated version of it. See C1.
Fusion strategy Decide when to combine signals: early fusion (shared encoder from the start) versus late fusion (separate encoders merged before the final layer). See L1.
Mixed-modality handoff Reason about transitions between modalities inside a conversation: when a voice turn should switch to a visual, or when a vision input should trigger an audio response. Mechanism in L7.

Evaluating and costing them

Modality-specific eval Design benchmarks and rubrics for non-text outputs where standard metrics like BLEU or exact match break down. See C1.
Latency budgets across modalities Allocate response-time budgets when vision, audio, and text encoders each add processing time before the model can begin. See C5, L0.
Modality-specific safety and refusal Calibrate refusal policies per modality: a harmful image prompt requires different detection logic than a harmful text prompt. See C2.
Multimodal cost attribution Track and attribute cost per modality: image tokens are priced differently from text tokens, and video multiplies image cost by frame count. See C5.
Note on mechanisms vs. disciplines: The encoders that convert images or audio into tokens are mechanisms that live in L1 (Model Training and Adaptation). The infrastructure that serves multimodal requests at runtime lives in L0 (Serving Infrastructure). C6 owns the discipline of reasoning across those mechanisms, not the mechanisms themselves.
