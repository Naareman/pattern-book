Capability Negotiation and Tool Discovery

Agents and tools announce what they can do at runtime. The caller asks, the other side replies with a menu, and the caller picks from what is on offer.

01What It Is

Ask first, then call.

Capability negotiation is a short handshake where the caller asks what tools the other side has, receives a list it can pick from, and needs no code change when new tools are added.

02An Example

Tap a step in the handshake.

Agent connects to a new tool server 3 steps
Agent → Tool server
{ "method": "tools/list" }

The agent does not assume. It asks the server what tools exist right now. This same call works against any server that speaks the protocol.

Tool server → Agent
{ "tools": [ { "name": "search_docs", "description": "Full-text search the help center", "input": { "query": "string" } }, { "name": "create_ticket", "description": "Open a new support ticket", "input": { "title": "string", "body": "string" } } ] }

The server replies with a menu. Each tool has a name, a short description, and the shape of its inputs. The agent now knows what is on offer (and can read the descriptions back to the model to decide which one fits the user's request).

Agent → Tool server
{ "method": "tools/call", "params": { "name": "search_docs", "arguments": { "query": "reset password" } } }

The agent picks from the menu. Tomorrow the server might list a new tool ("escalate_to_human"); the agent will see it on the next handshake and can use it straight away, without a deploy.

03Where It Fits

How it relates to nearby ideas.

What it covers
The short menu exchange at the start of a connection: who offers what, with which inputs. After that, the actual tool calls happen as normal.
Sits next to
Rides on top of an agent-to-agent protocol (how messages are shaped), checked by identity (which tools this caller may see), and often paired with a shared workspace (where results land).
04When It Matters

When to reach for it.

  • The set of available tools changes over time and you want agents to pick up new ones without a code change.
  • You build agents that should work with tools from many teams or vendors.
  • You want the tool descriptions themselves to guide the model toward the right choice for the user's request.

Sources
