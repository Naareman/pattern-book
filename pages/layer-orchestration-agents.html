Layer · L5

Orchestration

How the system organizes its calls across time, takes action in the world, and talks to other AI actors.

01The Idea

What Is It?

An agent does not just answer a question. It runs a loop: it thinks about what to do next, acts by calling a tool (a search engine, a calculator, some code), and observes the result. Then it loops back and thinks again. When it finally has enough, it gives you the answer. This loop is called Think - Act - Observe, and it lets the AI solve tasks that would need many separate steps from you.

03A Real Example

Where It Matters.

The task
A user asks: "Book me a flight to Madrid next Friday and add it to my calendar."
One call is not enough
The AI needs to search flights, pick the best option, confirm the booking, and then write the calendar event. Each step depends on the one before.
The agent loop
Think: search for flights. Act: call the flights tool. Observe: three options returned. Think: pick the cheapest. Act: call the booking tool. Observe: confirmed. Act: call the calendar tool. Done.
Why it works
The AI carries information forward across steps, the same way a person would. No human in the loop needed for each step.

05Inside This Layer

Everything that lives here.

Axis: how a system's calls and actions are organized across time, the world, and other actors.
Shape: Structure of Execution Across Calls
Single-Call Patterns
The entire task is answered in one round trip to the model. Nothing loops or fans out.
Sequential Pipelines
Steps run one after another in a fixed order. The output of each step feeds the next.
Parallel / Fan-Out / Fan-In
Multiple sub-tasks run at the same time and their results are gathered back into one answer.
Iterative Loops (ReAct, Reflection)
The model repeats a Think-Act-Observe cycle until it has enough to stop. The ReAct loop demonstrated above is this pattern.
Router / Dispatcher
An entry point inspects the request and sends it to whichever specialist or sub-pipeline is the right fit.
Hierarchical Planning (Planner-Executor)
A planner model breaks the goal into a high-level plan. Separate executor agents carry out each step of that plan.
Conditional Branching
The path through the system changes based on what the model or a check discovers at runtime.
Action: State-Changing Operations on the Outside World
External Action (State-Changing Tool Invocation)
The agent calls a tool that writes, books, sends, or otherwise changes something outside the model. A read-only search belongs in L3a, not here.
Idempotency and Action Verification
Ensuring the same action run twice leaves the world in the same state, and confirming the action actually succeeded.
Compensating Actions and Rollback
When a step fails mid-sequence, the system runs an undo operation to restore a safe state.
Approval Gates
The agent pauses and waits for a human to approve before a high-stakes action executes. The user-facing display of that pause lives in L7.
Side-Effect Sandboxing
Running potentially dangerous code or actions in an isolated environment so failures cannot escape to production.
Multi-Step Action Transactions
Treating a sequence of actions as one atomic unit: all succeed together or all roll back together.
Coordination: Communication Between Multiple Actors
Agent-to-Agent Protocols (MCP, A2A)
Standard message formats that let one AI agent call or delegate to another. MCP (Model Context Protocol) and A2A (Agent-to-Agent) are the current leading protocols.
Shared Workspace / Blackboard
Multiple agents read and write to a common space so they can build on each other's partial results without a direct hand-off.
Agent Identity and Auth
How an agent proves who it is, holds credentials securely, and operates with only the permissions it needs.
Capability Negotiation and Tool Discovery
Agents advertise what they can do, and callers discover which tools or sub-agents are available at runtime.
Filing rule: Shape = in what order or structure do calls execute? Action = what does the system do to outside state? Coordination = how do multiple actors communicate? When you see a ReAct loop, the loop itself is Shape. Each tool call inside the loop is Action.
