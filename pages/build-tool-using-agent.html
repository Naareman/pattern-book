Tool-using Agent Loop

The canonical agent: a model that thinks, calls a tool, reads the result, and decides what to do next, on repeat, until done or out of tries.

Default in 2026

ReAct loop, max 10 iterations, exponential backoff on tool errors. Pair with sealed tools (capability-scoped). Reference: Anthropic, Building Effective Agents.

01The Idea

What is it?

A model that thinks, acts, observes, repeats: at each turn it writes a thought, calls a tool, reads what came back, and decides whether to keep going or answer.

02See It Work

The ReAct loop, live.

Step through one bounded loop: three real iterations of Thought / Action / Observation, then the agent answers. Toggle the cap off to see what happens with no bound.

User task
"Find out whether requests==2.31.0 has any known CVEs in 2025 and recommend an upgrade."
Iter
0 / 10
Iter 1 Thought
I need CVE data for requests==2.31.0. The NVD database has machine-readable CVE records. I'll search there first.
Iter 1 Action
search_cve(package="requests", version="2.31.0", year=2025)
Iter 1 Observation
Returned 1 match: CVE-2025-1417 (medium, certificate-bypass). Fixed in 2.32.0.
Iter 2 Thought
One CVE, fix exists in 2.32.0. I should confirm that version is stable and check its release notes for breaking changes before recommending it.
Iter 2 Action
fetch_release_notes(package="requests", version="2.32.0")
Iter 2 Observation
Returned release notes. No breaking API changes. Drops support for Python 3.7. Patches CVE-2025-1417.
Iter 3 Thought
I have a clear answer: 1 CVE exists, 2.32.0 fixes it, no breaking changes. I can stop and respond.
Iter 3 Final answer
Yes, upgrade. requests==2.31.0 has one known 2025 CVE (CVE-2025-1417, certificate-bypass, medium severity), patched in 2.32.0. The upgrade has no breaking API changes; only drops Python 3.7 support.
Bounded execution active. Max iterations: 10. Tool errors retry with exponential backoff. Loop halts on final answer or when the cap is reached.
03A Real Example with Production Receipts

Named companies shipping this.

The tool-using ReAct loop is the most-shipped agent shape in 2026. Here are three reference implementations with real configs.

Anthropic Claude Code 2026 effective-harness post Coding agent
Claude Code's harness runs a ReAct-style loop with file-system, shell, and code-edit tools. Anthropic's Effective Harnesses for Long-Running Agents post recommends bounded iteration limits, structured tool error handling, and capability scoping so the agent cannot exceed its sandbox.
loop: ReAct (Thought / Action / Observation) max_iter: configurable, default bounded tools: Read, Edit, Bash, Grep, WebFetch (sealed) on_error: exponential backoff, structured retry termination: final answer OR cap OR user interrupt
anthropic.com/engineering/effective-harnesses-for-long-running-agents↗
Cursor Agent mode 2026 docs Coding agent
Cursor's Agent mode runs a tool-using loop over the user's repo: it reads files, runs commands, edits code, and re-reads its output until the task closes or the iteration budget is exhausted. Docs explicitly warn that tools must be capability-scoped and bounded.
loop: tool-use ReAct over repo + terminal tools: read_file, edit_file, run_terminal, search model: claude-opus-4.7 / gpt-5 (user choice) bounds: per-turn budget, repo-scoped
docs.cursor.com↗
OpenAI Agents SDK · Handoffs 2026 reference Framework
OpenAI's Agents SDK ships a ReAct loop primitive plus a Handoffs feature: when the current agent decides it needs a specialist, it can hand off the task to another agent with its own tools and bounded loop. Both loops are independently capped.
loop: tool-call cycle (function-calling JSON) max_turns: 10 (override per agent) handoffs: delegate to specialist agent with own loop tracing: built-in (every iteration logged)
openai.github.io/openai-agents-python↗
04The Price You Pay

What it costs.

lowhigh
Token cost per task
Latency (tool round-trips)
Failure surface (tool errors)
Runaway risk (without cap)
Reasoning ceiling
The loop pays compounding token cost per iteration and inherits every tool's failure modes. The bound is non-negotiable: without it, a confused agent will loop on bad observations until your bill or rate limit stops it. With a cap and exponential backoff, this is the most powerful single-agent shape available in 2026.
05Patterns It Uses

It decomposes into.

Two layers in play: the cognitive strategy (how the model reasons through tool use) and the orchestration shape (how the loop is structured and bounded).

L4 Cognitive Strategy: ReAct prompting interleaves Thought / Action / Observation in one stream L5 Shape: Iterative loops repeat the call until a stopping rule fires L5 Action: External Action reaches outside the model (search, code, APIs) L5 Shape: Bounded Execution caps iterations so the loop cannot run forever
06When to Use vs Alternatives

The decision.

Use a Tool-using Agent Loop when the task needs more than one tool call, but the work is still single-track and single-session.
If the task needs no tools or only a fixed pipeline (no choice at runtime)
→
Single call (no loop)
If the task needs persistent session, sub-agents, and a long-running brain / hands split
→
Agent Harness
If the task has natural levels (plan, then specialists, then synthesis)
→
Hierarchical Multi-Agent
If the task needs tools and a bounded number of think-act-observe rounds
→
Tool-using Agent Loop
