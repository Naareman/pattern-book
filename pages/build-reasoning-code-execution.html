Reasoning System with Code Execution (PAL)

Instead of computing in its head, the model writes a short program, runs it, and drops the real result into its answer.

01The Idea

What is it?

Language models (LLMs, the AI models you send a prompt to: the text you type and send) are surprisingly bad at arithmetic and multi-step logic when they try to reason inside their own "head." PAL (Program-Aided Language model) sidesteps that weakness entirely. The model is asked to write a small program that encodes the reasoning steps. A sandboxed interpreter then runs it, and the correct, computed result is inserted directly into the final answer.

02See It Work

Watch the code run.

See the difference between a model that tries to do the math in its head versus one that writes and runs code. Toggle the mode, then step through.

# The model writes this: no arithmetic yet monday = 127 tuesday = 84 wednesday = 213 restock = 500 sold_so_far = monday + tuesday + wednesday total = sold_so_far + restock print(total)
2 Execute: sandboxed interpreter runs it waiting
Output 924
3 Answer: result drops into the response waiting
The bakery will have baked 924 muffins in total by the end of restocking (127 + 84 + 213 sold, plus 500 more to bake).
1 Attempt: work through it mentally waiting
Monday and Tuesday: 127 + 84 = 201 211. Then 211 + 213 = 414 424. Add restock: 424 + 500 = 914 924.
⚠  Intermediate slip: carried the wrong digit. Off by 10.
2 Answer: wrong number, no error signal waiting
The bakery will have baked 914 muffins in total by the end of restocking.
The model sounds confident. There is nothing in the output that flags the error.
03A Real Example

How it runs in practice.

This is what happens when a math tutor app uses PAL to answer a student's homework problem. The user only sees the final answer; all code is internal.

Step 1: Prompt with a few examples
The prompt (the text sent to the model) includes 2 to 3 solved examples, each showing the word problem and the Python code that solves it. This is few-shot framing: the model learns the pattern by example, not by instruction.
Step 2: Model writes code
The model generates a short Python snippet. It does no arithmetic: it only encodes the structure of the problem as variable assignments and arithmetic operators.
Step 3: Sandboxed execution
The snippet runs in a sandboxed interpreter (a locked environment with no internet access, no file writes, time-limited) so it cannot cause side effects. The numerical result is captured.
Step 4: Result injected into the answer
The model is called again (or the result is templated in) so the final answer contains the computed number, not the model's mental guess. The student sees a friendly explanation, not a code dump.

A minimal Python-based PAL prompt. Each example shows the problem then the code; the model continues the pattern for a new problem.

# System: You solve word problems by writing Python.
# Always end with print(answer).

## Example 1
# Q: Alice has 45 apples. She gives 12 to Bob. How many remain?
apples = 45
given  = 12
answer = apples - given
print(answer)  # 33

## Example 2
# Q: A train travels at 80 km/h for 2.5 hours. Distance?
speed    = 80
hours    = 2.5
answer   = speed * hours
print(answer)  # 200.0

## Your turn
# Q: A bakery sells 127 muffins Monday, 84 Tuesday, 213 Wednesday.
#    They bake 500 more to restock. Total muffins baked?
# (model continues here...)
04Patterns It Uses

The pieces inside.

PAL stitches together three layers, which is why no single layer name covers it on its own.

Single-call control
Chain-of-Thought (externalized)
Every reasoning step is written as a line of code, so the code itself is the chain of thought.
Single-call control
Few-Shot Framing
A few solved examples in the prompt teach the model what code style to write, no fine-tuning needed.
Stateless Retrieval
Sandboxed Pure-Functional Execution
Running the code changes nothing (no disk writes, no network), so it counts as read-only.
Orchestration & agents
Sequential Pipeline
Three steps in strict order: write code, run it, compose the final answer.
Why no single layer name fits: writing the code happens inside one model call, running it is read-only retrieval, and chaining the steps is orchestration. PAL crosses all three, so it is best described by the combination, not by any one layer.
Sequencing
1Model call 1: prompt with few-shot examples + word problem. Model outputs Python code only.
2Sandboxed interpreter: execute the snippet, capture stdout. On error: surface to user or retry.
3Model call 2 (or template): combine the original problem + computed result into a natural-language answer.
