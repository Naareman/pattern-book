Record who did what, when

Every prompt, every tool call, every refusal lands in a tamper-resistant log. Months later, a question like "why did the agent send that email?" has a clean answer.

01What is it?

What is it?

An audit log is an append-only record of every meaningful event the system ran: who asked, which prompt was sent, which tool was called, what came back, what the policy allowed, what was refused. Each entry carries a timestamp, the user, the tenant, and a request id so the trail can be stitched back together. The point is later, not now: when someone asks "what happened on Tuesday at 14:02?", the log has a single, faithful answer.

02An example

Tap a line to see the full entry.

A slice of one customer's audit log on a quiet Tuesday afternoon. Tap any row to expand it.

audit.log · tenant: acme · 2026-05-26
request_id: req_8a21f4 user: priya@acme.com action: retrieve(docs, query="Q1 revenue") policy: allow tokens_in: 142 tokens_out: 388 latency_ms: 820
Append-only and signed. Once a line is written, nothing inside the running system can rewrite it. That property is what turns the log from "useful" into "proof".
03Where it fits

How it relates to nearby ideas.

What it covers: the long-lived record of who asked what and what the system did about it. Time-ordered, append-only, written for later.
Sits next to: observability traces are kept for engineers debugging this week. Audit logs are kept for legal and security reviewing this year. Same raw events: different audience, different retention, different access.
Quick test: if a regulator asked you to reconstruct one user's full interaction from six months ago, could you do it down to which model version, which tool, and which document was retrieved? If yes, the audit log earns its name.
04When it matters

When to reach for it.

  • You are pursuing SOC 2, ISO 27001, HIPAA, or a similar audit: a tamper-resistant trail is a hard requirement.
  • The agent can take real actions: sending money, posting to customers, changing records. Each action needs a clean record of who authorised it.
  • You expect to hand a copy of one user's full history back to that user under a data-access request.
