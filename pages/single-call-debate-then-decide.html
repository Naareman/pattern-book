Debate-Then-Decide

The model argues both sides of a question before committing to an answer, so the decision is reached after genuinely stress-testing it rather than after one-sided reasoning.

01What It Is

Both sides, then a verdict.

The model is prompted to act as its own devil's advocate: generate the strongest case for one position, then generate the strongest case against it, and only then produce a final judgment. Because both arguments must be stated in full, the model is forced to surface the considerations it might otherwise skip over. The key concept is single-model debate: the same model runs both sides within one call, rather than using two separate agents or calls. This keeps the pattern in L4 and avoids the latency and coordination cost of a multi-model setup.

02An Example

Should we cache this API response?

Decision: Should the product search API response be cached for 24 hours?
For
  • Cuts average response time from 420 ms to under 30 ms for repeat queries.
  • Reduces upstream API costs by an estimated 70% during peak hours.
  • Product catalog changes at most twice daily, so staleness risk is low.
Against
  • Flash sales can change prices within minutes; stale prices cause support tickets.
  • Stock-out events happen without warning; a cached "in stock" response loses sales.
  • 24-hour TTL is arbitrary: no analysis backs that specific number.
Verdict
Cache for 5 minutes, not 24 hours. Speed benefit is real, but inventory and price accuracy risk at 24 h is too high. Invalidate on any price or stock-level change event.
03Where It Fits

Its place in the taxonomy.

L4
Home layer
Self-Verification sub-axis of Single-Call Control. Both sides of the debate and the final verdict are generated inside one call to one model. No second call, no second model.
L5
Not this
If two separate agents are instantiated (one per side) and their outputs are reconciled by an orchestrator, that is L5 Coordination, not L4. The single-call boundary is the filing rule.
L2
Not this
If a separate judge model scores or selects between two independently generated outputs, that is L2 Verify. A verdict written by the same model inside the same call is L4.
Filing rule: Self-checking inside one call to one model = L4 Self-Verification. A separate verifier call or a different model = L2 Verify.
04When It Matters

Who needs this.

Best suited to decisions where the first plausible answer is often the wrong one: architectural trade-offs, policy choices, product prioritization. It is especially useful when the model has an implicit prior toward one option (for example, a bias toward action over inaction) and needs a prompt to genuinely articulate the opposing case. The output also serves as documentation: the "for" and "against" sections give reviewers a transparent record of the reasoning behind the decision.
