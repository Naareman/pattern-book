Structural Composition

How multiple model calls are organized into a single good answer: combine, choose, or check.

01The Idea

What is it?

One answer from one LLM (large language model, the AI that reads and writes text) can be wrong. Structural Composition fixes that by deciding how multiple model calls are organized into one reliable answer. The three moves: fuse several outputs together (Combine), pick the best one from a set of candidates (Select), or gate the answer through a separate judgment step (Verify).

02See It Work

Ask three times, vote.

The same question goes to the model three times. Each run gives a slightly different answer. Then a vote picks the most common one.

Question A train leaves at 14:00 and arrives 2 hours 40 minutes later. What time does it arrive?
A
Run 1
14:00 + 2 h 40 min = 16:40
16:40
B
Run 2
2 hours after 14:00 is 16:00, plus 40 minutes is 16:40
16:40
C
Run 3
14 + 2 = 16, then 0 + 40 = 40 ... so 16:30
16:30
Vote count:
16:40 0
16:30 0
✓
16:40 wins (2 votes to 1).
The majority answer is chosen, and the lone outlier is discarded.
03A Real Example

Real examples.

🔗
Chaining
The output of one step becomes the input of the next.
A research tool first asks the model to find the key claim in an article, then passes that claim into a second call that checks whether it is supported by a cited source. Each step is narrow and easy; together they do something neither could alone.
🗳
Voting (self-consistency)
Run the same question several times, take the most common answer.
Medical triage software asks its diagnosis model three times with slightly different prompts. If two out of three agree, that answer goes forward. The disagreeing run is discarded. This catches the cases where a single run would give an unlucky wrong answer.
🔀
Routing
Send the question to the model best suited for it.
A customer service platform classifies incoming messages first. Simple greetings go to a small fast model. Legal or billing questions go to a bigger, more careful model. The user gets the right quality at the right cost without seeing any of that complexity.
04Tradeoffs

Combine runs the most calls and costs the most, but gives the highest accuracy gain. Select is cheap but depends on a good routing classifier. Verify adds one extra judgment call and catches errors without multiplying cost as aggressively as full voting.
05Inside This Layer

Every category in L2.

Axis: how multiple potential model calls are organized into a single answering act.
Combine

Multiple outputs are fused together to produce one result.

Ensembling (vote, average, blend)
Run the same or similar question through several models or prompts (the instructions you send the AI), then combine the outputs by majority vote, numerical average, or weighted blend.
Decomposition and Recomposition
Break a complex task into independent sub-tasks, solve each with its own model call, then reassemble the pieces into a final answer.
Select

One output is chosen from a set of candidates.

Cascading (Cheap to Expensive)
Try the smallest, cheapest model first. If its confidence is high enough, stop. Otherwise escalate to a larger, more capable model.
Confidence-Based Routing
Inspect the model's confidence score on its own output. Route low-confidence outputs to a stronger model or a fallback path.
Specialist-of-Experts Routing
A classifier reads the incoming question and sends it to whichever specialist model is best matched to that topic or task type.
Verify

One output is gated, scored, or revised by a separate judgment step.

Verification Composition (LLM-as-Judge)
A second LLM call is used specifically to judge whether the first answer is correct, faithful, or high-quality. The judge's verdict determines whether the output passes.
Generator-Critic Pairs
One model generates a draft. A separate critic model reviews that draft and flags problems. The generator may then revise based on the critic's notes.
Output Filtering by Classifier
A fast classifier (not necessarily an LLM) scans the model's output for policy violations, format errors, or low quality, and blocks or flags outputs that fail.
Filing rule: fused from multiple outputs = Combine. Chosen from candidates = Select. Gated or scored by a separate judgment = Verify. Self-checking inside one call is L4 Single-Call Control, not L2.
Note on Self-Consistency: when N samples come from the same model with the same prompt (in-decoding search), that is L4. When the samples use different models or different prompts, it is L2 Combine (Ensembling). The boundary is implementation, not intent.
