Paged attention

Store the model's running notes in small even-sized pages instead of one big reserved slab. The same GPU then holds far more users at once.

01What is it?

Many small pages, no wasted seats.

Paged attention splits each user's in-flight memory into small fixed-size blocks mapped by a lookup table, so the GPU never reserves space it does not immediately need and fits far more users in parallel.

What changes: on the left, each user grabbed a big block sized for a worst-case answer and left most of it empty. On the right, each user grows page by page as they actually need room, so the GPU can host two to four times as many people on the same hardware.
03Where it fits

Where it sits.

Common uses
Built into open serving engines (vLLM made it famous), now standard in production stacks. It is the memory side of how many users one GPU can serve.
Pairs with
Answering many at once. Modern batching mixes users of very different lengths in one pass; the paged layout is what makes that practical.
Different from
Slimming the model. That makes the model itself smaller. This rearranges where each user's running memory lives.
04When it matters

When to reach for it.

  • Many users with very different reply lengths share the same model.
  • You see "out of memory" errors long before the GPU is really full.
  • Cost per user is your bottleneck and you want to squeeze more of them onto the same hardware.
